# 爱冒险玖日 · 游戏网站

一个**暗色高级、有科技感**的网页游戏网站。支持游客浏览、用户注册登录，以及唯一管理员在后台自由地**创建、编辑、删除**游戏（可自定义封面 + 填入游戏链接）。

网站结构（对应需求）：

- 全屏渐变首页 Hero（真实视频背景 + 大标题 + 导航栏 + 联系按钮）
- 「可以游玩的游戏」横向卡片区（来自后台数据，点开即玩）
- 「关于 · 个人经历」头像 + 介绍 + 联系方式 + 项目数据
- 「精选项目」大卡片作品墙
- 「底部联系」整屏收尾页（一键进入 B 站主页）

## 如何启动

直接双击项目根目录下的 **`start.cmd`** 即可（它会自动找到本机的 Node 运行环境）。

启动后浏览器访问：

- 网站首页：<http://localhost:3009>
- 管理后台：<http://localhost:3009/admin>

> 端口默认 `3009`，如需改端口，可在 `start.cmd` 中给 `server.js` 传环境变量，例如将 `node server/server.js` 改为 `set PORT=8080` 后再运行。

### 开发者功能

- **申请成为开发者**：登录后，点击导航栏的「申请开发者」，填写说明并提交。管理员在后台「开发者申请」里**同意/拒绝**；同意后该用户即成为「开发者」。
- **开发者发布游戏**：开发者进入 `/developer`（开发者中心），可自行发布游戏：
  - **网页游戏**（点开即玩）：填网页游戏地址，卡片会标注「网页游戏」。
  - **需下载到电脑运行**：填百度网盘等下载链接，卡片会标注「需下载 · 电脑运行」。
  - 两种链接**二选一**；可上传封面、设标签、勾选精选。
- 开发者只能**编辑/删除自己发布**的游戏，不能修改别人的。
- 开发者发布的游戏会**优先展示在首页**，同时在管理后台出现「待审核」提示。管理员**通过**则长期保留；**驳回**则直接删除。
- 管理员在后台也可对任意游戏「编辑/删除」，并查看每个游戏的类型、状态与归属开发者。

访问地址：

- 网站首页：<http://localhost:3009>
- 管理后台：<http://localhost:3009/admin>
- 开发者中心：<http://localhost:3009/developer>

- **个人介绍、联系方式、项目（精选作品）**：属于静态内容，直接编辑 [`public/index.html`](public/index.html) 里的对应文字即可。页面邮箱已统一为 `3114844060@qq.com`，收尾页按钮点击跳转你的 B 站主页。
- **Hero 背景视频**：想换成自己的视频，把视频放到 `public/assets/video/` 下，命名为 `hero.mp4`（或 `hero.webm`），刷新即自动播放。没有视频时会自动使用内置的动画 + 海报背景，也不会报错。

## 技术说明

- 后端：纯 Node.js 内置模块（`server/server.js`），**无需安装任何第三方依赖**。
- 数据：本地 JSON 文件（`data/db.json`），上传的封面存放在 `uploads/`。
- 登录：签名 Cookie 会话，密码以 scrypt 加盐哈希存储。
- 前端：原生 HTML / CSS / JavaScript，PC 优先，内容版心约 1700px。

开发辅助脚本（可选，均位于 `server/`）：
- `gen_assets.py`：重新生成视觉素材（氛围图、头像、项目图等）。
- `gen-video.js`：用浏览器生成一段 Hero 背景视频（WebM）。
- `build-static.js`：打包一个“纯静态可玩版”到 `build/netlify/` 并生成 `build/netlify-static.zip`。

## 怎么把它公开让别人访问

这个网站有两部分：**前端页面**（人人能看）+ **后端**（注册/登录、后台管理、游戏数据和封面上传）。所以“公开”有两个层次：

### 方式一：纯静态可玩版（最省事，适合直接分享）

已经为你生成了一个 **`build/netlify-static.zip`**。它会像你的游戏一样，上传到 Netlify 就能得到一个永久公网地址。

1. 打开 <https://app.netlify.com/drop>
2. 把 `build/netlify-static.zip` 拖进去（或解压后把整个文件夹拖进去）
3. 稍等片刻，它会给你一个类似 `https://xxxx.netlify.app` 的网址，把这个链接发给别人即可

> **注意：** 这种“静态版”只保留“看游戏 + 点卡片新窗口玩”，**没有**账号注册/登录和后台管理（因为纯静态站点没有后端）。游戏列表是打包进去的；以后要换游戏，改完请重新执行 `node server/build-static.js` 再上传一次。

### 方式二：完整版（保留在线后台，游戏可随时在线增删改）

完整版需要一个“能跑 Node.js + 带持久化磁盘”的平台，推荐 **Railway**（免费、适合这个项目）。项目已配置好 Dockerfile、`package.json`、健康检查 `/api/health`、`DATA_DIR` 持久化支持，以及后台在线改密码。

以 Railway 为例：
1. 把本项目推到 GitHub（仓库要在根目录含 `package.json` 与 `Dockerfile`）。
2. 在 Railway「New Project → Deploy from GitHub」选择该仓库，它会自动识别并部署（优先用 Dockerfile）。
3. 在该服务 `Settings → Volumes` 添加一块卷，**挂载路径填 `/data`**（游戏、用户、封面都存在这里，重启/更新都不丢）。
4. 在该服务 `Variables` 设置两个环境变量：
   - `DATA_DIR=/data`（必须，指向上面的卷）
   - `ADMIN_PASSWORD=你的强密码`（部署环境的管理员初始密码，务必改成强密码；数据库里还没有 admin 时才生效）
5. 部署后打开返回的 `https://xxxx.up.railway.app` 地址；首次启动会自动创建管理员 `admin`，用你设置的 `ADMIN_PASSWORD` 登录。
6. 后台管理：打开地址 `/admin`，可在线增删改游戏 / 上传封面 / 改密码。

> 说明：`PORT` 平台会自动注入。若用其它免费平台（Render / Fly.io 等），同样原理——要 **挂载持久化卷并设 `DATA_DIR` 指向它**；Render 免费档没有持久化磁盘，因此更推荐 Railway 或 Fly.io。

自带的一键部署入口：把仓库推上 GitHub 后，可在 [railway.app](https://railway.app) 通过仓库导入；也可用 Railway CLI 在本目录执行 `railway up`。
